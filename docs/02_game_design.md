# 02. 게임 설계

대상: 초등 고학년. 부스 PC/태블릿 가로 화면 우선, 모바일 반응형. 한 판 목표 시간: **부스 모드 8~10분**, 전체 모드 20분 내외.

## 1. 화면 흐름

```
Title ─▶ Nickname(닉네임만, 2~10자) ─▶ StageSelect(1단계만 열림, 클리어 시 다음 해금)
  ─▶ Learn(학습 카드 + 챗봇, 스테이지마다) ─▶ Play(타워디펜스 + 실시간 퀴즈 팝업)
  ─▶ (클리어) 다음 스테이지 / (실패) 같은 스테이지 재도전
  ─▶ Result(점수·통계) ─▶ Review(AI 오답 정리, 틀린 문제 다시 풀기) ─▶ Leaderboard(기록 등록·순위)
  ─▶ 다시 도전(새 세션)
```

- Learn 화면은 건너뛸 수 있지만, 카드를 끝까지 넘기면 **학습 보너스 코인 +50**을 준다(감점은 없음).
- Play 화면은 세로 모바일에서도 깨지지 않게 캔버스를 화면 폭에 맞춰 스케일한다(내부 해상도 1024×576 고정).

## 3. 맵

- 격자 16×9, 타일 64px. `config/maps/<topicId>.ts`에 경로 웨이포인트(타일 좌표 배열)와 건설 가능 타일을 정의한다.
- 경로는 S자 또는 U자 1개. 시작점(왼쪽 가장자리) → 성(오른쪽 가장자리).
- 타워는 건설 가능 타일에 1개씩. 경로 타일·성 타일에는 못 짓는다.
- 배경은 `render/background.ts`가 주제별 팔레트·간단한 도형(지붕, 나무, 파도)으로 그린다. 외부 이미지 없음.

| 옵션 | 한 단계 효과 | 최대 | 1단계 비용(기본 비용 ×) | 가진 타워 |
|---|---|---|---|---|
| 💥 위력 | 피해 +35% | 3 | 0.6 | 전부 |
| ⚡ 연사 | 공격 속도 +30% | 3 | 0.6 | 전부 |
| 💣 폭탄 | 폭발 반지름 +0.5칸(단일 → 범위) | 3 | 0.8 | 온천·거북선·종탑 |
| 🌀 관통 | 관통 +1마리 | 3 | 0.7 | 피리 |
| ✌️ 쌍발 | 한 번에 +1발(다른 대상, 없으면 같은 대상) | 2 | 1.0 | 온천·피리·종탑·만세 |
| 🎯 사거리 | 사거리 +20% | 2 | 0.5 | 거북선·만세 |

  같은 옵션은 올릴수록 비싸진다: n단계 비용 = 기본 비용 × 계수 × (1 + 0.5 × (n−1)). 표시 레벨 = 1 + 총 횟수, 타워 위에 ★(3개까지, 그 이상 ★N).

- 조준 우선순위: 기본 '성에 가장 가까운 적', 거북선은 '체력 최대 적'.

## 6. 실시간 퀴즈 팝업

- 트리거(`config/waves.quizMarksFor`): 시간이 아니라 **몬스터 수** 기준. 웨이브당 문제 수 = 몬스터 수 ÷ 12(2~3개)이며 **웨이브 시작 1문제** + 그 뒤 균등 간격의 스폰 수 지점에서 1문제. 보스 웨이브는 마지막 자리를 **보스 등장 직전 긴급 퀴즈**가, 러시 웨이브는 앞자리를 **역사 러시(2문제)** 가 차지한다. 스폰이 끝난 뒤(보스전) 30초(전체 모드 35초) 동안 문제가 없고 몬스터가 남아 있으면 1문제 보조 출제. 부스 모드 스테이지당 약 7문제(1웨이브 2, 2웨이브 2, 3웨이브 3).
- 팝업이 뜨면 **게임을 일시정지**하고 **제한시간 15초** 타이머를 보여 준다. 시간 초과는 오답으로 처리하되 감점 없음.
- 문제는 스테이지 시작 시 서버에서 받은 `quizBatch`에서 순서대로 사용한다. 같은 판에서 같은 원본 문제는 다시 나오지 않는다(변형 포함). 배치가 바닥나면 서버에 추가 요청.
- 난이도 배정(`domain/quiz_rules.py`) — 전체 모드(5웨이브): 웨이브 1~2 → 난이도 1, 웨이브 3~4 → 1·2 섞음, 웨이브 5 → 2·3. **부스 모드(3웨이브)**: 웨이브 1 → 1, 웨이브 2 → 1·2, 웨이브 3 → 2·3. 종류별: 긴급 퀴즈 → 2·3, 역사 러시 → 1·2.
- 채점은 서버(`POST /quiz/answer`). 응답이 오기 전에는 로컬에서 정답 여부를 모르므로, 팝업은 "확인 중" 상태를 0.3초 이내로 보여 준 뒤 서버 응답으로 결과를 표시한다. 네트워크 실패 시 1회 재시도 후 문제를 무효 처리(코인 0, 콤보 유지)하고 게임 재개.
- 오답: 코인 0, **콤보 초기화**, 오답 목록에 기록. 정답 해설을 3초간 보여 주고 게임 재개.

### 코인 보상 (서버 계산, 클라이언트는 표시만)

```
base        = 30 (일반) | 50 (긴급 퀴즈) | 40 (역사 러시 문항)
comboMult   = 1 (콤보 1) | 2 (콤보 2) | 3 (콤보 3 이상)
fastBonus   = +10 (5초 이내 정답)
eventMult   = 2 (코인 2배 타임 중) | 1
coins       = (base × comboMult + fastBonus) × eventMult
```

## 8. 클리어·실패·재도전

- 클리어: 최종보스 처치. 남은 코인은 점수로 환산(아래 공식), 다음 스테이지 시작 코인은 다시 100 + 학습 보너스.
- 실패: 성 체력 0. "다시 도전" 시 같은 스테이지를 처음부터 (같은 세션, 문제는 아직 안 나온 것 우선). 재도전 횟수 제한 없음. 서버는 `stages/{n}/start`에 `retry:true`가 오면 그 스테이지의 **이벤트 횟수 상한(중간보스·최종보스·웨이브 클리어)만 초기화**하고, 정답·콤보·코인 통계는 세션에 계속 누적한다.
- 포기: 어느 화면에서든 "그만하기" → 현재까지 점수로 결과 화면.

## 9. 점수 공식 (서버가 계산, `domain/scoring.py`)

```
score = correctCount × 100
      + comboMax × 50
      + wavesCleared × 150
      + stagesCleared × 500
      + livesLeftAtEnd × 30
      + min(coinsLeftAtEnd, 500)
```

- 서버가 아는 값: `correctCount`, `comboMax`(퀴즈 로그), `stagesStarted`, 이벤트 기록.
- 클라이언트가 보고하는 값: `wavesCleared`, `stagesCleared`, `livesLeftAtEnd`, `coinsLeftAtEnd`.
- 검증(초과 시 등록 거부 + 로그): `stagesCleared ≤ stagesStarted`, `wavesCleared ≤ wavesPerStage × stagesStarted`, `0 ≤ livesLeft ≤ 10`, `coinsLeft ≤ coinsFromQuiz(서버) + MAX_CLIENT_BONUS_PER_STAGE × stagesStarted + MAX_CLIENT_BONUS_PER_WAVE × wavesCleared`.
  - 두 상수는 `domain/scoring.py`에만 둔다. 스테이지당 = 시작 코인 100 + 학습 보너스 50 + 만피 보너스 100 + 콤보 마일스톤 100 + 보스 처치 180 (2배 타임 여유 포함해 넉넉히), 웨이브당 = 처치 코인 최대치 + 황금 슬라임 50 + 웨이브 보너스 최대치 (2배 타임 여유 포함). 밸런스 조정(Phase 3.11) 때 함께 손본다.

## 10. 결과·오답 정리·리더보드

- Result: 점수, 정답률, 최대 콤보, 도달 스테이지, 이번 판 획득 코인 총합.
- Review: 틀린 문제를 서버(`POST /review`)가 Gemini로 일괄 해설. 문항마다 "다시 풀기" 버튼(로컬 채점, 점수 반영 없음). 틀린 문제가 없으면 "완벽해요!" 카드.
- Leaderboard: 닉네임·점수·도달 스테이지 상위 20. 같은 닉네임 중복 허용(개인정보 없음). 부적절 닉네임은 서버가 거부.

## 11. 접근성·아동 친화

- 글자 크기 최소 18px, 버튼 최소 48px, 색만으로 정보를 전달하지 않음(아이콘·문구 병기).
- 퀴즈 문항은 한 화면에 들어오게(문장 60자, 보기 25자 목표).
- 효과음은 선택(기본 켬, 토글 제공). Web Audio로 코드 생성 톤을 쓰거나 무료 효과음 파일을 `public/assets/sfx/`에 둔다(저작권 확인된 것만).
